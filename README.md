# metal-crypto

Apple Metal (GPU) implementations of SHA-1, SHA-256, SHA-512, AES-CTR,
BIP32 private-key derivation, and secp256k1 field/point arithmetic, all
validated against published test vectors.

## Files

| File | Purpose |
|---|---|
| `crypto.metal` | The Metal shader library (all kernels). |
| `sha_consts.h` | SHA-256/512 round constants + IVs (generated, C and Metal branches). |
| `aes_tables.h` | AES S-box and encryption T-tables Te0..Te3 (generated, C and Metal branches). |
| `vectors.h` | Test vectors (generated by `gen_vectors.py`). |
| `ref.c` | Host C reference mirroring the shader logic 1:1; runs all vectors with `gcc`. |
| `run_metal_shim.cpp` | Executes the actual `crypto.metal` source on the host via a C++ shim (`metal_shim.h`) and checks all vectors. |
| `main.m` | On-device macOS harness that runs the compiled `.metallib` on the GPU against the same vectors. |
| `gen_vectors.py`, `gen_sha_consts.py`, `gen_aes_tables.py` | Regenerate vectors/tables. |

## Kernels in crypto.metal

- `sha1_batch` / `sha256_batch` / `sha512_batch` — one thread per message;
  inputs are a data blob plus per-message `offsets`/`lens`; outputs are
  concatenated digests (20/32/64 bytes per thread).
- `aes_ctr_kernel` — AES-128/256 in CTR mode; one thread per 16-byte block,
  T-table round function (`Te0..Te3` in `constant` memory), 128-bit
  big-endian counter increment per thread.
- `secp_field_mul_kernel` — secp256k1 field multiplication mod p
  (8×32-bit limbs, pseudo-Mersenne reduction 2^256 ≡ 2^32 + 977).
- `secp_mul_g_kernel` — scalar multiplication k·G, Jacobian coordinates,
  4-bit windowed (64 digits, precomputed table of 16 multiples), one
  field inversion (Fermat, a^(p-2)) at the end.
- `bip32_master_kernel` — BIP32 master key from seed (HMAC-SHA512 "Bitcoin seed").
- `bip32_ckd_priv_kernel` — BIP32 CKDpriv (hardended and normal derivation;
  normal uses the compressed public key from `secp_mul_g_kernel`).

## Speed choices

- 32-bit limbs everywhere in secp256k1: 64-bit integer ALU ops are
  reduced-rate on Apple GPUs, and every 32×32→64 product still fits a
  full-rate 64-bit multiply. The pseudo-Mersenne form of p keeps reduction
  to two 33-bit folds, each split so no intermediate exceeds 64 bits.
- AES uses the classic 4-table T-table round (4 lookups + 4 XORs per round per
  block); CTR parallelizes perfectly, one block per thread, no chaining.
- SHA-256/SHA-512 rounds are `#pragma unroll`-ed; SHA-512 is streaming so
  HMAC-SHA512 reuses it without extra copies.
- Scalar multiplication uses a 4-bit window (256 doublings → 64 adds) instead
  of 128 additions for plain double-and-add.

## Build and validate

Host-side (Linux/macOS, no GPU needed) — validates the exact shader source:

```
g++ -std=c++14 -O2 -I. -include metal_shim.h -x c++ run_metal_shim.cpp -o run_metal_shim
./run_metal_shim        # expect: RESULT: ALL PASS (37 checks)
gcc -O2 -o ref ref.c && ./ref   # C reference: RESULT: ALL PASS (40 checks)
```

On-device (macOS):

```
xcrun -sdk macosx metal -c crypto.metal -o crypto.air
xcrun -sdk macosx metallib crypto.air -o crypto.metallib
clang -framework Metal -framework Foundation main.m -o metaltest
./metaltest crypto.metallib    # expect: RESULT: ALL PASS
```

## Test vectors

- SHA-1/SHA-256/SHA-512: empty, "abc", the 56-byte NIST string, 55/56/64/1000-byte edge cases (hashlib-generated).
- AES-128-CTR / AES-256-CTR: NIST SP 800-38A F.5.1 / F.5.5, plus a 33-byte partial-block case (openssl-generated).
- secp256k1: (p−1)² mod p, 5⁻¹ mod p, a·b mod p, 2G, and k·G for a 256-bit k (Python big-int generated).
- BIP32: test vector 1 from the BIP32 spec (seed `000102...0f`, path m/0'/1/2'/2/1000000000), cross-checked against the published master key and m/0' values.
